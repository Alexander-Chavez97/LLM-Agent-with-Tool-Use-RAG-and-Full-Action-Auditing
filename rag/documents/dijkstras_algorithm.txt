Dijkstra's Algorithm

Dijkstra's algorithm finds the shortest path from a single starting node to all other nodes in a weighted graph, provided none of the edge weights are negative. It works by maintaining a running "best known distance" to every node, starting at zero for the source and infinity for everything else, and repeatedly selecting the unvisited node with the smallest known distance to process next.

When a node is processed, the algorithm looks at each of its outgoing edges and checks whether reaching a neighboring node through the current node would be shorter than that neighbor's currently known distance. If so, the neighbor's distance is updated, a step commonly called "relaxing" the edge. Once a node has been selected and processed, its shortest distance is considered final and will never be revisited, which is what makes the algorithm efficient rather than exhaustive.

The requirement that edge weights be non-negative is fundamental, not a minor caveat. The algorithm's correctness relies on the assumption that once a node is chosen as having the smallest tentative distance, no other unvisited node could later provide a shorter path to it -- but a negative edge weight could violate that assumption by making a longer-looking path suddenly cheaper after the fact. Graphs with negative weights instead require an algorithm like Bellman-Ford, which is slower but tolerates negative edges as long as there is no negative cycle.

A naive implementation runs in O(V^2) time for V vertices, since finding the minimum-distance unvisited node each round requires scanning them all. Using a priority queue (typically a binary or Fibonacci heap) to retrieve the minimum efficiently improves this to O((V + E) log V), which is the standard implementation used in practice for anything beyond small graphs. This algorithm underlies many real routing systems, including network packet routing protocols and mapping applications computing driving directions.
