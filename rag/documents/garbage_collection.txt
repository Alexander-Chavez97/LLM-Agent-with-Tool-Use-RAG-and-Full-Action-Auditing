Garbage Collection

Garbage collection is an automatic memory management technique that reclaims memory occupied by objects a program no longer needs, removing the need for developers to manually track and free every allocation themselves. Languages like Java, Python, and Go rely on garbage collection, in contrast to languages like C, where the programmer is directly responsible for freeing every allocated block of memory.

A widely used approach is reference counting, where each object keeps track of how many references point to it, and the object is freed the moment that count reaches zero. This is simple and reclaims memory promptly, but it has a well-known weakness: two objects that reference each other, forming a cycle, will never have their reference count drop to zero even if nothing outside the cycle refers to either of them, causing a memory leak unless a separate cycle-detection mechanism is layered on top.

Tracing garbage collectors take a different approach, periodically starting from a set of known "root" references (such as global variables and each thread's active stack) and following every reachable reference outward, marking every object found along the way as still in use. Anything not marked after this traversal is, by definition, unreachable by the program and can be safely reclaimed. This correctly handles reference cycles, since an isolated cycle unreachable from any root is simply never marked.

Modern tracing collectors are frequently generational, based on the empirical observation that most objects become garbage very shortly after being allocated, while a smaller set of objects survive for a long time. Generational collectors separate objects into a young generation, collected frequently and cheaply, and an old generation, collected less often, promoting objects to the old generation once they survive enough collection cycles. This significantly reduces the average cost of garbage collection compared to scanning the entire heap on every pass.
