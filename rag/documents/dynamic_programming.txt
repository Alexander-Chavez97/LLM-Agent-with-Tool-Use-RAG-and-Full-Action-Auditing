Dynamic Programming

Dynamic programming is a technique for solving problems by breaking them into overlapping subproblems, solving each subproblem once, and reusing those solutions rather than recomputing them. It applies specifically to problems that exhibit two properties: optimal substructure, meaning an optimal solution to the problem can be constructed from optimal solutions to its subproblems, and overlapping subproblems, meaning a naive recursive solution would end up solving the exact same subproblem many times.

The classic illustration is computing Fibonacci numbers. A naive recursive implementation recomputes the same smaller Fibonacci values repeatedly -- computing fib(5) involves computing fib(3) twice and fib(2) three times -- causing exponential time complexity that grows extremely fast even for modest inputs. Dynamic programming fixes this by storing each subproblem's result the first time it is computed, so any later request for that same subproblem is a simple lookup instead of a recomputation, reducing the same calculation to linear time.

There are two common implementation styles. Top-down (memoization) keeps the natural recursive structure of the problem but adds a cache, typically a hash table or array, to store and check for previously computed results before recursing further. Bottom-up (tabulation) instead builds a table of subproblem results iteratively, starting from the smallest subproblems and working up to the final answer, avoiding recursion and its associated call-stack overhead entirely.

Recognizing when a problem is a good fit for dynamic programming is itself the harder skill, more so than implementing it once recognized. Common signals include problems asking for an optimal value (minimum cost, maximum profit, longest sequence) where a brute-force solution would need to explore many overlapping choices -- classic examples include the knapsack problem, longest common subsequence, and edit distance between two strings.
